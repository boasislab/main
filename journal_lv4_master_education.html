지금까지 만든 LV2 교육자료, ASSIGN/ARG 점검표, LV3 자율학습 원천자료, 로컬 HTML 교육자료를 하나의 교육 흐름으로 다시 엮은 마스터 페이지입니다. 원천 식별자는 최소화하고, 운영자가 이해해야 할 구조와 검증 관점에 집중했습니다.

복식부기 분개장 거래유형 분개모형 상품/계정 매핑 ASSIGN/ARG 원장·마감·오류대응
이 페이지는 LV4 게이트 뒤에 둔 회사업무 교육 허브입니다. GitHub Pages의 클라이언트 비밀번호는 강한 보안 수단이 아니므로, 민감 원문 파일 다운로드와 상세 쿼리/운영 식별자는 싣지 않았습니다. 전체 원천 파일 묶음은 별도 iMessage ZIP으로 전달된 로컬 자료를 기준으로 보관합니다.

1. 교육 목표와 큰 그림

분개처리는 거래 데이터를 회계 언어로 바꾸는 과정이다. 시스템 관점에서는 원천 거래, 거래유형, 분개모형, 계정속성, 상품/계정 매핑, 금액 세팅 방식이 결합되어 최종 분개장이 만들어진다.
1. 회계 기초부기, 복식부기, 차변/대변, 분개의 개념을 잡습니다.
2. 시스템 구조거래유형과 상품/계정 축이 어떻게 결합되는지 봅니다.
3. 금액 세팅ASSIGN과 ARG 방식으로 분개 라인 금액이 채워지는 원리를 이해합니다.
4. 운영 검증원장, 마감, 대사, 오류 대응까지 확인합니다.

2. 부기와 복식부기

단식부기

현금의 입출금처럼 한쪽 방향만 기록하는 방식입니다. 가계부나 단순 현금 관리에는 편하지만, 자산·부채·손익의 변화를 함께 설명하기 어렵습니다.

  • 기록이 단순합니다.
  • 미수금, 미지급금, 평가손익, 환산손익 관리에 약합니다.
  • 장부 오류를 체계적으로 검증하기 어렵습니다.

복식부기

하나의 거래를 차변과 대변 양쪽에 기록합니다. 무엇이 늘었는지와 그 증가의 원천이 무엇인지 함께 남기는 방식입니다.

  • 자산 = 부채 + 자본의 등식을 유지합니다.
  • 차변 합계와 대변 합계가 항상 일치해야 합니다.
  • 결산, 보고, 감사 추적의 기반이 됩니다.

금융기관이 복식부기를 쓰는 이유

  1. 채권, 주식, 파생상품, 외화, 미수/미지급, 평가손익처럼 한 거래가 여러 항목에 동시에 영향을 줍니다.
  2. 현금주의뿐 아니라 발생주의 회계를 처리해야 합니다.
  3. 차대 검증을 통해 오류를 빠르게 감지할 수 있습니다.
  4. 총계정원장, 보조원장, 결산자료, 대외보고 자료로 이어지는 일관된 기록 체계가 필요합니다.

3. 분개와 장부의 관계

용어의미운영 관점
부기거래를 장부에 기록하는 방식회계 기록의 전체 체계
분개차변/대변 계정과 금액을 정하는 작업거래를 회계 언어로 바꾸는 첫 단계
분개장분개 결과가 거래 단위로 저장되는 장부원천 거래와 회계 장부를 잇는 핵심 결과물
총계정원장분개를 계정별로 집계한 장부잔액, 결산, 보고의 기준
보조원장상품·거래·자산별 세부 장부총계정원장과 대사하는 세부 근거

4. 자동분개 전체 흐름

원천 거래작업일자, 거래유형, 상품, 통화, 수량, 금액 등을 받습니다.
거래유형 판단분개 대상 여부와 사용할 분개모형을 판단합니다.
분개모형 조회차변/대변 라인, 순번, 계정속성, 금액 기준을 가져옵니다.
상품계정 매핑상품 성격과 계정속성 조합으로 실제 계정을 확정합니다.
금액 세팅원천값 직접 세팅 또는 집계값 순번 세팅을 적용합니다.
차대 검증차변 합계와 대변 합계가 맞는지 확인합니다.
분개장 저장검증된 결과를 분개장과 후속 원장 처리로 넘깁니다.
원장 대사계정원장, 보조원장, 평가자료와 정합성을 확인합니다.

5. 거래유형 축과 상품/계정 축

거래유형 축

거래유형은 어떤 업무 거래인지, 분개가 발생해야 하는지, 어떤 분개모형을 읽을지를 결정합니다.

  • 분개 발생 대상 여부
  • 공통분 또는 CASE별 처리
  • 자금/실물/회계 연계 여부
  • 정정 또는 결산 시 별도 기준 필요 여부

상품/계정 축

상품/계정 축은 분개모형에서 나온 계정속성이 실제 어떤 계정으로 바뀌는지 결정합니다.

  • 상품의 회계 분류
  • 투자목적, 기간, 통화 등 보조 조건
  • 계정속성과 상품계정의 결합
  • 실제 계정 확정과 원장 반영
거래유형은 “어떤 분개 구조를 만들지”를 정하고, 상품/계정 매핑은 “그 구조의 계정속성을 어떤 실제 계정으로 치환할지”를 정한다.

6. 분개모형의 역할

구성요소설명검증 포인트
분개 라인한 거래가 몇 개의 차변/대변 줄로 나뉘는지 정의라인 누락 또는 중복 여부
차대변 구분각 라인이 차변인지 대변인지 결정차변 합계와 대변 합계 일치 여부
계정속성실제 계정 전 단계의 회계 성격상품계정 매핑으로 실제 계정 확정 가능 여부
금액 기준어떤 원천값 또는 집계값을 라인에 넣을지 결정금액/수량/단가/환율 혼동 여부
적용 상태적용기간, 사용 여부, 승인 상태현재 거래일자에 의도한 모형이 호출되는지

7. ASSIGN / ARG 방식

ASSIGN 방식

원천 거래에 이미 존재하는 값을 특정 분개 라인에 직접 연결하는 방식입니다. 단건 거래의 원천 금액이 명확할 때 적합합니다.

  • 매매, 결제, 이자, 배당 등
  • 원천 항목의 업무 의미 확인이 핵심
  • Null 값, 금액/수량 착오, 세전/세후 혼동에 주의

ARG 방식

여러 데이터를 먼저 집계하거나 계산한 뒤, 정해진 순번에 따라 분개 라인에 값을 넣는 방식입니다. 집합분개에 적합합니다.

  • 평가, 상각, 환산, 결산 등
  • ARG 순번과 분개 라인 의미의 일치가 핵심
  • 집계 기준, 대상 누락, 재처리 기준 차이에 주의
구분ASSIGNARG
데이터 출처개별 거래 원천값사전 집계·계산 결과값
적합 업무거래별 금액이 명확한 처리평가·상각·환산 등 집합 처리
주요 위험잘못된 원천 항목, Null 값, 금액/수량 착오순번 오류, 집계 기준 오류, 대상 누락
검증원천 거래 상세와 라인 금액 1:1 대조집계 산출 근거와 라인별 금액 대조

8. 원장과 손익

분개장

거래별 차변/대변 라인이 저장되는 출발점입니다.

계정원장

분개장의 계정별 합계와 잔액을 관리합니다.

보조원장

상품·거래·자산별 세부 내역을 관리하고 계정원장과 대사합니다.

손익 유형원인분개 관점
평가손익시장가격 변동보유 중인 자산의 장부가 조정
환산손익환율 변동외화 잔액의 원화 환산 차이
매매손익자산 처분처분 결과의 실현 손익 인식
환차손익외화 결제결제 시점 환율 차이 반영

9. 외화 자산 분개 처리

취득 시점

외화 취득금액을 원화로 환산하고 취득가, 부대금액, 미수/미지급 성격을 구분합니다.

보유 평가

시장가격 변동은 평가손익, 환율 변동은 환산손익으로 분리해서 봅니다.

수익 수령

이자·배당 등 현금흐름과 발생주의 인식 시점 차이를 구분합니다.

처분/결제

가격 차이는 매매손익, 환율 차이는 환차손익으로 구분합니다.

10. 일일 처리와 마감 흐름

기초 세팅전일 잔액과 기준정보를 당일 시작점으로 이월합니다.
기준정보가격, 환율, 이자율, 배당 등 기준값을 확인합니다.
거래평가매수, 매도, 결제, 수익 수령 등 원천 거래 기반 분개를 생성합니다.
장부평가경과이자, 상각, 보수 등 기간 발생 금액을 반영합니다.
공정평가시장가격과 환율 기준으로 평가/환산 손익을 반영합니다.
회계마감분개장, 계정원장, 보조원장 정합성을 확인하고 확정합니다.
대사잔액, 수량, 금액, 손익이 서로 맞는지 비교합니다.
보고결산과 대외 보고의 근거 자료로 사용합니다.

11. 운영 점검 체크리스트

  • 거래유형이 분개 대상인지 확인했다.
  • 의도한 분개모형이 호출되는지 확인했다.
  • 차변/대변 라인 수와 의미를 확인했다.
  • 계정속성이 실제 계정으로 매핑되는지 확인했다.
  • ASSIGN 원천값의 의미와 Null 가능성을 확인했다.
  • ARG 순번과 집계 결과의 의미를 대조했다.
  • 차변 합계와 대변 합계가 일치하는지 확인했다.
  • 원장과 보조원장 대사 결과를 확인했다.
  • 적용기간, 사용 여부, 승인 상태를 확인했다.
  • 정정 또는 재처리 영향 범위를 확인했다.
  • 변경 전후 설정과 테스트 결과를 기록했다.
  • 대표 정상 케이스와 예외 케이스를 모두 테스트했다.

12. 오류 대응 흐름

오류 발견분개장, 원장, 대사 결과에서 불일치를 찾습니다.
원인 분류분개모형, 매핑, 금액, 원천 거래, 마감 상태로 나눕니다.
영향 범위거래, 상품, 계정, 일자 범위를 확인합니다.
정정 방식재처리, 역분개, 수정분개, 매핑 보정 중 선택합니다.
정정 처리통제 절차에 따라 수정하고 이력을 남깁니다.
재검증차대변, 원장 잔액, 보조원장 대사를 다시 확인합니다.
기록 보관원인, 조치, 검증 결과를 교육/운영 자료로 남깁니다.
재발 방지체크리스트와 테스트 케이스를 보강합니다.

13. 교육 진행 순서

  1. 부기와 분개의 차이를 설명한다.
  2. 단식부기와 복식부기를 비교한다.
  3. 금융기관에서 복식부기가 필요한 이유를 설명한다.
  4. 분개가 복식부기의 출발점임을 설명한다.
  5. 자동분개 전체 흐름을 설명한다.
  6. 거래유형과 분개모형의 역할을 설명한다.
  7. 계정속성과 실제 계정 매핑을 설명한다.
  8. ASSIGN과 ARG 방식을 비교한다.
  9. 원장, 손익, 외화, 마감 흐름으로 확장한다.
  10. 오류 사례와 운영 점검 체크리스트로 마무리한다.
