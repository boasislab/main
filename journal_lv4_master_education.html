1. 분개란 무엇인가?

정의와 구성요소
분개는 하나의 거래를 회계 장부에 기록하기 위해 차변 계정, 대변 계정, 금액, 거래 식별값을 정하는 작업이다. 시스템에서는 거래처리 프로그램이 만든 원천 데이터가 분개모형과 계정매핑을 거쳐 분개장 라인으로 전환된다.

업무 관점의 정의

거래가 발생했을 때 무엇이 증가하고 무엇이 감소했는지를 차변과 대변으로 나누어 표현하는 회계 처리의 출발점이다.

  • 거래의 경제적 의미를 계정으로 번역한다.
  • 차변과 대변 금액이 일치해야 한다.
  • 분개 결과는 분개장과 원장 대사의 기준이 된다.

시스템 관점의 정의

거래코드, 상품코드, 투자목적, 장단기, 원천 금액을 입력값으로 받아 분개모형을 조회하고 저장용 분개장 구조를 만드는 처리다.

  • 거래코드는 어떤 분개모형을 사용할지 정한다.
  • 상품/계정 매핑은 실제 계정을 확정한다.
  • ASSIGN/ARG는 금액을 어디서 가져올지 정한다.
구성요소의미교육 포인트
차변/대변거래를 양쪽 회계 효과로 나누는 구분합계 일치 여부가 첫 번째 검증 포인트다.
계정거래 효과를 분류하는 회계 항목계정속성과 상품조건이 결합되어 실제 계정이 정해진다.
금액원천 거래 컬럼 또는 산식으로 산출되는 값금액 컬럼, 부호, 통화, 산식 방향을 함께 확인한다.
분개모형거래유형별 분개 라인 설계도거래 1건이 몇 개의 분개장 라인으로 전개되는지 보여준다.
분개장확정된 분개 결과가 저장되는 장부원장, 결산, 대외보고의 기초 자료가 된다.

2. 금융기관은 왜 복식부기를 쓰는가

분개의 출발점

단식부기

현금 입출금처럼 한쪽 방향만 기록합니다. 단순하지만 자산·부채·손익의 동시 변화를 설명하기 어렵습니다.

  • 소규모 현금 관리에는 적합
  • 미수/미지급, 평가손익, 환산손익 관리에 취약
  • 장부 오류 검증 구조가 약함

복식부기

하나의 거래를 차변과 대변에 동시에 기록합니다. 무엇이 늘었는지와 그 증가의 원천을 함께 남깁니다.

  • 자산 = 부채 + 자본 등식을 유지
  • 차변 합계와 대변 합계로 오류 검증
  • 결산, 보고, 감사 추적의 기반
금융기관 관점복식부기가 필요한 이유
거래의 양면성채권 매입은 채권 증가와 현금 감소가 동시에 발생한다.
발생주의현금이 오가기 전에도 미수이자, 수익, 비용을 인식해야 한다.
평가와 환산보유 중인 자산도 가격과 환율 변화로 장부가가 바뀐다.
통제와 보고원장, 결산, 대외보고, 감사 대응을 위해 계정별 추적성이 필요하다.

4. 자동분개 엔진의 처리 흐름

7단계 구조
1. 원천 거래작업일자, 거래유형, 상품, 통화, 금액을 수신한다.
2. 거래유형 판단분개 대상 여부와 사용할 분개모형을 판단한다.
3. 분개모형 조회차대 라인, 순번, 계정속성, 금액 기준을 가져온다.
4. 계정 확정상품 성격과 계정속성을 결합해 실제 계정을 정한다.
5. 금액 세팅원천값 직접 세팅 또는 집계값 순번 세팅을 적용한다.
6. 차대 검증차변 합계와 대변 합계가 맞는지 확인한다.
7. 저장·대사분개장 저장 후 원장과 보조원장을 대사한다.
8. 마감 반영일일 마감과 결산 보고의 근거로 사용한다.

6. 거래유형 축과 상품/계정 축을 분리해서 본다

구조 이해의 핵심

거래유형 축

어떤 업무 거래인지, 분개가 발생해야 하는지, 어떤 분개모형을 읽을지를 결정합니다.

  • 분개 발생 대상 여부
  • 공통분 또는 CASE별 처리
  • 자금/실물/회계 연계 여부
  • 정정 또는 결산 시 별도 기준

상품/계정 축

분개모형에서 나온 계정속성이 실제 어떤 계정으로 바뀌는지 결정합니다.

  • 상품의 회계 분류
  • 투자목적, 기간, 통화 등 조건
  • 계정속성과 상품계정의 결합
  • 실제 계정 확정과 원장 반영
거래유형은 “어떤 분개 구조를 만들지”를 정하고, 상품/계정 매핑은 “그 구조의 계정속성을 어떤 실제 계정으로 치환할지”를 정한다.

7. 분개모형은 구조를 만들고, 계정매핑은 실제 계정을 정한다

구성요소설명검증 포인트
분개 라인한 거래가 몇 개의 차변/대변 줄로 나뉘는지 정의라인 누락 또는 중복 여부
차대변 구분각 라인이 차변인지 대변인지 결정차변 합계와 대변 합계 일치 여부
계정속성실제 계정 전 단계의 회계 성격상품계정 매핑으로 실제 계정 확정 가능 여부
금액 기준어떤 원천값 또는 집계값을 라인에 넣을지 결정금액/수량/단가/환율 혼동 여부
적용 상태적용기간, 사용 여부, 승인 상태현재 거래일자에 의도한 모형이 호출되는지

8. ASSIGN / ARG는 금액을 채우는 방식이다

ASSIGN 방식

원천 거래에 이미 존재하는 값을 특정 분개 라인에 직접 연결합니다. 단건 거래의 원천 금액이 명확할 때 적합합니다.

  • 매매, 결제, 이자, 배당
  • 원천 항목의 업무 의미 확인이 핵심
  • Null 값, 금액/수량 착오, 세전/세후 혼동에 주의

ARG 방식

여러 데이터를 먼저 집계하거나 계산한 뒤, 정해진 순번에 따라 분개 라인에 값을 넣습니다. 집합분개에 적합합니다.

  • 평가, 상각, 환산, 결산
  • ARG 순번과 분개 라인 의미의 일치가 핵심
  • 집계 기준, 대상 누락, 재처리 기준 차이에 주의
구분ASSIGNARG
데이터 출처개별 거래 원천값사전 집계·계산 결과값
적합 업무거래별 금액이 명확한 처리평가·상각·환산 등 집합 처리
주요 위험잘못된 원천 항목, Null 값, 금액/수량 착오순번 오류, 집계 기준 오류, 대상 누락
검증원천 거래 상세와 라인 금액 1:1 대조집계 산출 근거와 라인별 금액 대조

13. 오류 대응은 원인 분류부터 시작한다

오류 발견분개장, 원장, 대사 결과에서 불일치를 찾는다.
원인 분류분개모형, 매핑, 금액, 원천 거래, 마감 상태로 나눈다.
영향 범위거래, 상품, 계정, 일자 범위를 확인한다.
정정 방식재처리, 역분개, 수정분개, 매핑 보정 중 선택한다.
정정 처리통제 절차에 따라 수정하고 이력을 남긴다.
재검증차대변, 원장 잔액, 보조원장 대사를 다시 확인한다.
기록 보관원인, 조치, 검증 결과를 교육/운영 자료로 남긴다.
재발 방지체크리스트와 테스트 케이스를 보강한다.
