회사 분개처리 통합교육자료

거래가 발생한 뒤 회계 분개장으로 확정되기까지의 개념, 매핑 구조, 자동/수동 처리, 검증 포인트와 오류 대응 흐름을 한 번에 볼 수 있도록 정리한 공유용 교육자료입니다.

공유용 일반화 분개모형 ASSIGN/ARG 상품/계정 매핑 원장 검증 손익/외화 처리 마감 흐름
이 페이지는 교육 공유용입니다. 내부 테이블명, 컬럼명, 프로그램명, 실제 코드값, 화면번호는 싣지 않고 구조와 업무 흐름 중심으로 정리했습니다.

1. 학습 순서

1. 발생 구조분개장이 왜 거래유형과 상품/계정 매핑의 결합 결과인지 먼저 잡습니다.
2. 구성요소원천 거래, 거래유형, 분개모형, 계정속성, 상품계정 매핑의 역할을 구분합니다.
3. 처리 순서원천값 수신부터 실제 계정 확정과 분개장 저장까지 순서대로 봅니다.
4. 회계 원칙차변/대변, 복식부기, 자동/수동분개의 기준을 이해합니다.
5. 후속 검증원장 반영, 손익 유형, 외화 처리, 대사, 오류 대응 흐름으로 마무리합니다.

2. 분개장 발생 핵심 구조

분개장은 거래유형이 정한 분개모형과 상품/계정 매핑이 결합되어 만들어진다. 분개모형은 차변/대변 라인과 계정속성을 정하고, 상품계정 매핑은 그 계정속성을 실제 계정으로 바꾼다.

거래유형 축

  • 어떤 업무 거래인지 식별합니다.
  • 분개 발생 대상인지 판단합니다.
  • 분개모형을 통해 몇 줄의 차변/대변이 필요한지 정합니다.
  • 각 분개 라인이 어떤 계정속성을 가져야 하는지 제공합니다.

상품/계정 축

  • 거래 대상 상품의 회계 분류를 확인합니다.
  • 상품별 계정상품 기준을 찾습니다.
  • 계정속성과 상품계정의 조합으로 실제 계정을 확정합니다.
  • 같은 거래유형이라도 상품 성격에 따라 다른 계정으로 분기될 수 있습니다.

3. 전체 처리 흐름

1. 원천 거래 수신작업일자, 거래유형, 상품, 통화, 수량, 금액 등 입력값을 받습니다.
2. 거래유형 확인분개 대상 여부와 어떤 분개모형을 사용할지 판단합니다.
3. 분개모형 조회차변/대변 라인, 순번, 계정속성, 금액 기준을 가져옵니다.
4. 상품계정 확인상품의 분류와 목적에 맞는 계정상품 기준을 찾습니다.
5. 실제 계정 확정계정속성과 상품계정 매핑을 결합해 실제 계정을 정합니다.
6. 금액 세팅원천 거래의 금액, 환율, 평가값 등을 분개 라인에 반영합니다.
7. 분개장 저장검증을 통과한 결과를 분개장과 후속 원장 처리로 넘깁니다.

4. 주요 구성요소 역할

구성요소 역할 교육 포인트
원천 거래 분개 생성의 입력값을 제공합니다. 분개장은 원천 거래 없이 독립적으로 만들어지지 않습니다.
거래유형 어떤 분개모형을 읽을지 결정합니다. 거래유형은 계정코드를 직접 확정하기보다 분개 구조를 선택합니다.
분개모형 차변/대변, 순번, 계정속성, 금액 기준을 정의합니다. 분개모형은 실제 계정이 아니라 계정의 성격을 먼저 만듭니다.
계정속성 취득가, 미수수익, 손익, 예수금처럼 계정의 의미를 표현합니다. 분개모형과 실제 계정을 이어주는 중간 키입니다.
상품계정 매핑 상품 성격과 계정속성을 결합해 실제 계정을 찾습니다. 상품이 달라지면 같은 계정속성도 다른 계정으로 치환될 수 있습니다.
분개장 원천값, 분개모형 결과, 확정 계정, 금액이 저장되는 최종 결과입니다. 거래유형 축과 상품/계정 축의 결합 산출물입니다.

5. 처리 순서 상세

  1. 원천 거래에서 작업일자, 거래유형, 상품, 통화, 수량, 금액 등을 수신합니다.
  2. 거래유형 기준으로 분개 발생 대상 여부를 확인합니다.
  3. 분개 대상이면 거래유형에 맞는 분개모형을 조회합니다.
  4. 분개모형에서 차변/대변 라인과 계정속성을 생성합니다.
  5. 상품 기준으로 계정상품 매핑을 확인합니다.
  6. 계정상품과 계정속성을 결합해 실제 계정을 확정합니다.
  7. 원천 금액과 분개 라인, 확정 계정을 조합합니다.
  8. 차변 합계와 대변 합계를 검증한 뒤 분개장에 저장합니다.
  9. 분개장 결과를 계정원장과 보조원장 대사 기준으로 활용합니다.

6. 분개처리란 무엇인가

정의

분개처리는 거래를 회계 언어로 바꾸는 과정입니다. 거래의 경제적 의미를 차변과 대변으로 나누고, 금액과 계정을 확정해 분개장에 기록합니다.

목적

거래 원천값을 회계 원장에 반영하고, 이후 잔액 조회, 결산, 대사, 보고 자료의 기준 데이터로 사용할 수 있게 만듭니다.

8. 분개모형의 역할

항목 설명 교육 포인트
분개 라인 한 거래가 몇 개의 차변/대변 줄로 나뉘는지 정의합니다. 복잡한 거래는 하나의 입력에서 여러 분개 라인이 생성됩니다.
차대변 구분 각 라인이 차변인지 대변인지 정합니다. 차변 합계와 대변 합계가 일치해야 합니다.
계정속성 취득가, 미수수익, 손익, 예수금처럼 계정의 의미를 표현합니다. 아직 실제 계정이 아니라 실제 계정을 찾기 위한 중간 기준입니다.
금액 기준 원천 거래의 어떤 금액을 어떤 라인에 넣을지 정합니다. 거래금액, 결제금액, 평가금액, 환율 적용 금액 등이 분리될 수 있습니다.
분개모형 시각화 — 한 거래가 여러 분개 라인으로 펼쳐지는 방식
차변

거래의 경제적 효과 중 자산 증가, 비용 발생, 미수 성격 금액을 표현합니다.

금액 기준 원천 거래 금액, 평가금액, 환율 적용 금액
차변

경과이자, 미수수익, 수수료처럼 본 거래와 함께 분리 관리해야 하는 금액을 담습니다.

계정 결정 계정속성 + 상품계정 매핑
대변

현금 감소 또는 수익 성격 라인

결제금액, 지급금액, 수익 발생처럼 반대편 회계 효과를 기록합니다.

검증 기준 차변 합계와 대변 합계 일치

9. ASSIGN / ARG 금액 세팅 방식

분개모형은 차변/대변 라인과 계정속성을 정하고, ASSIGN / ARG 방식은 각 라인에 어떤 금액을 넣을지 정한다. 즉, 계정의 성격을 정하는 단계와 금액을 세팅하는 단계는 구분해서 관리해야 한다.
개별 거래 직접 세팅

ASSIGN 방식

원천 거래에 이미 존재하는 금액, 수량, 환율, 결제값 등을 특정 분개 라인에 직접 연결하는 방식입니다.

  • 매매, 결제, 이자/배당 수령처럼 거래 단위가 명확한 경우에 적합합니다.
  • 어떤 원천 항목을 가져오는지 업무 의미를 먼저 확인해야 합니다.
  • Null 값, 금액/수량 착오, 세전/세후 금액 혼동이 차대 불일치로 이어질 수 있습니다.
집계·계산 결과 세팅

ARG 방식

여러 거래나 보유 내역을 먼저 집계·계산한 뒤, 정해진 순번에 맞춰 분개 라인에 금액을 넣는 방식입니다.

  • 평가, 상각, 환산처럼 여러 데이터를 묶어 계산하는 경우에 적합합니다.
  • ARG 순번과 분개 라인의 의미가 정확히 대응되어야 합니다.
  • 집계 기준, 대상 누락, 순번 뒤바뀜, 재처리 기준 차이가 주요 오류 원인입니다.
원천값 확인거래 금액, 평가값, 환율, 수수료 등 사용할 값의 의미를 확인합니다.
분개모형 조회차변/대변 라인과 계정속성을 확인합니다.
방식 확인라인별 금액이 직접 세팅인지 집계 세팅인지 구분합니다.
금액 세팅ASSIGN은 원천 항목을 직접 연결하고, ARG는 집계 결과를 순번대로 연결합니다.
차대 검증합계 일치, 누락 라인, 반올림 차이를 확인합니다.
분개장 저장검증을 통과한 결과만 후속 원장 처리로 넘깁니다.
구분 ASSIGN 방식 ARG 방식
데이터 출처 개별 거래 원천값을 직접 사용 집계·계산된 결과값을 순번 기준으로 사용
적합한 업무 거래별 금액이 명확한 매매, 결제, 수익 수령 평가, 상각, 환산처럼 여러 건을 묶는 처리
관리 핵심 원천 항목의 의미, Null 가능성, 금액/수량 구분 순번 설계, 집계 기준, 대상 범위, 재처리 일관성
주요 오류 잘못된 항목 연결, 빈 값, 세전/세후 금액 혼동 순번 뒤바뀜, 집계 대상 누락, 계산 기준 불일치
검증 포인트 원천 거래 상세와 분개 라인 금액을 1:1로 대조 집계 산출 근거와 분개 라인별 금액을 대조
운영자가 분개모형을 관리할 때는 “어떤 계정으로 갈 것인가”와 “어떤 금액을 넣을 것인가”를 분리해서 봐야 합니다. 계정속성·상품계정 매핑은 계정 확정의 문제이고, ASSIGN / ARG는 금액 세팅과 검증의 문제입니다.

기능 관점 관리 항목

항목군 관리 시 주의사항 잘못 설정했을 때 영향 변경 후 테스트
거래/상품 식별 거래유형과 상품 성격이 서로 맞는지 확인합니다. 의도하지 않은 거래에 분개가 생성되거나 필요한 거래가 누락됩니다. 대표 거래를 만들어 의도한 분개모형이 호출되는지 확인합니다.
차대변 라인 차변/대변 라인 수와 각 라인의 역할을 먼저 검토합니다. 한쪽 라인이 빠지거나 반대로 생성되어 차대 불일치가 발생합니다. 라인별 금액과 차변/대변 합계를 대조합니다.
계정 결정 계정속성이 실제 계정으로 바뀌는 기준을 확인합니다. 회계 장부의 계정 과목이 잘못 확정됩니다. 상품별로 실제 계정이 올바르게 확정되는지 확인합니다.
금액 세팅 ASSIGN 직접 연결인지 ARG 집계 연결인지 구분합니다. 금액 누락, 금액 왜곡, 집계 기준 오류가 발생합니다. 원천값 또는 집계 산출 근거와 분개 라인 금액을 비교합니다.
통제 상태 적용기간, 사용 여부, 승인 상태가 업무 시점과 맞는지 확인합니다. 현재 거래가 분개되지 않거나 과거 거래가 의도치 않게 재처리됩니다. 적용기간 안팎의 거래를 각각 테스트합니다.
변경 검증 변경 사유, 영향 범위, 승인 근거, 테스트 결과를 남깁니다. 오류 발생 시 원인 추적이 어렵고 같은 문제가 반복됩니다. 변경 전후 대표 거래와 회귀 테스트 결과를 비교합니다.

10. 자동분개와 수동분개

자동분개

  • 정형화된 거래를 기준으로 시스템이 자동 생성합니다.
  • 거래유형, 분개모형, 상품계정 매핑, 원천 금액이 결합됩니다.
  • 대량 거래 처리와 반복 업무에 적합합니다.

수동분개

  • 예외, 조정, 특수 처리처럼 담당자 판단이 필요한 경우 사용합니다.
  • 입력 즉시 차대변, 계정, 금액 검증이 필요합니다.
  • 사유와 근거를 남겨 후속 대사와 감사 추적이 가능해야 합니다.

11. 주요 원장과 분개장의 관계

분개장

거래별 차변/대변 라인이 저장되는 출발점입니다. 계정별 누계의 근거가 됩니다.

계정원장

분개장의 계정별 합계와 잔액을 관리합니다. 결산과 잔액 검증의 중심입니다.

보조원장

상품, 거래, 보수, 평가 등 세부 내역을 관리합니다. 계정원장 잔액과 대사합니다.

평가 기준 자료

가격, 환율, 평가금액처럼 장부 조정과 손익 계산에 필요한 기준값을 제공합니다.

미결/보수 내역

결제 전 거래와 수수료성 금액을 추적해 원장 잔액과 비교할 수 있게 합니다.

12. 손익 유형

미실현 손익

평가손익

보유 자산의 장부가와 공정가가 달라질 때 발생합니다. 실제 처분 전이라도 장부가를 현재 가치에 맞추기 위해 분개가 필요합니다.

미실현 손익

환산손익

외화 금액은 그대로인데 환율이 바뀌면서 원화 장부금액이 달라지는 경우입니다. 외화 자산과 부채의 평가 과정에서 확인합니다.

실현 손익

매매손익

자산을 실제로 처분할 때 처분금액과 장부금액의 차이로 확정됩니다. 거래가 완료되면 수익 또는 비용으로 인식합니다.

실현 손익

환차손익

외화 거래가 실제 결제될 때 적용 환율 차이로 발생합니다. 환산손익과 달리 결제 시점에 손익이 확정됩니다.

13. 외화 자산 분개 처리

외화 거래는 외화 금액과 원화 장부금액을 함께 봐야 한다. 취득, 보유 평가, 이자/배당 수령, 처분/결제 시점마다 적용 환율과 손익 성격이 달라진다.

취득 시점

  • 외화 취득금액을 거래일 환율로 원화 환산합니다.
  • 취득가, 부대금액, 미수/미지급 성격의 금액을 구분합니다.
  • 외화 원금과 원화 장부금액이 모두 후속 검증의 기준이 됩니다.

보유 평가 시점

  • 시장가격 변동은 평가손익으로 확인합니다.
  • 환율 변동은 환산손익으로 구분합니다.
  • 두 손익이 섞이지 않도록 평가 기준과 환율 기준을 분리합니다.

수익 수령 시점

  • 이자, 배당, 수수료 등 현금흐름이 실제 들어오는 시점의 환율을 확인합니다.
  • 미수로 잡혀 있던 금액은 수령 시점에 제거됩니다.
  • 수익 인식과 현금 수령의 시점 차이를 분리해서 봅니다.

처분/결제 시점

  • 장부금액과 실제 결제금액의 차이를 확정합니다.
  • 가격 차이는 매매손익, 환율 차이는 환차손익으로 구분합니다.
  • 처분 후 보유수량과 장부잔액이 남지 않는지 확인합니다.

14. 일일 처리와 마감 흐름

기초 세팅
전일 잔액과 기준정보 이월전일 확정된 원장 잔액, 보유현황, 기준정보를 당일 처리의 시작점으로 세팅합니다.
기준정보
시장정보와 공시성 정보 반영가격, 환율, 이자율, 배당 등 분개 금액 산정에 필요한 기준정보를 확인합니다.
거래평가
개별 거래 분개 생성매수, 매도, 결제, 수익 수령 등 원천 거래 기반의 분개가 만들어집니다.
장부평가
발생주의 금액 반영경과이자, 상각, 보수처럼 기간에 따라 발생하는 금액을 회계적으로 반영합니다.
공정평가
평가손익과 환산손익 반영시장가격과 환율 기준으로 장부가를 조정하고 손익을 구분합니다.
회계마감
원장 확정과 대사분개장, 계정원장, 보조원장의 정합성을 확인한 뒤 해당 일자의 회계 결과를 확정합니다.

15. 검증 포인트

  1. 차변 합계와 대변 합계가 일치하는지 확인합니다.
  2. 거래유형에 맞는 분개모형이 존재하는지 확인합니다.
  3. 계정속성이 상품계정 매핑과 결합되어 실제 계정으로 확정되는지 확인합니다.
  4. 원천 거래의 금액, 수량, 환율, 평가값이 분개 라인에 올바르게 반영되는지 확인합니다.
  5. 분개장 합계와 계정원장, 보조원장 잔액이 서로 맞는지 대사합니다.
  6. 오류 수정 시 원분개, 역분개, 수정분개의 관계가 추적 가능해야 합니다.

16. 오류 대응 흐름

오류 발견분개장, 원장, 대사 결과에서 불일치를 확인합니다.
원인 분류분개모형, 매핑, 금액, 원천 거래, 마감 상태 중 어디 문제인지 나눕니다.
영향 범위 확인해당 거래, 상품, 계정, 일자 범위를 확인합니다.
정정 방식 결정재처리, 역분개, 수정분개, 매핑 보정 중 적절한 방법을 선택합니다.
정정 처리통제 절차에 따라 수정하고 처리 이력을 남깁니다.
재검증차대변, 원장 잔액, 보조원장 대사를 다시 확인합니다.
기록 보관원인, 조치, 검증 결과를 교육/운영 자료로 남깁니다.

계정 미확정계정속성, 상품계정 매핑, 계정 사용 가능 여부매핑 기준 보정 후 재처리 또는 수정분개

핵심 요약

분개처리는 거래유형이 정한 분개모형과 상품/계정 매핑이 결합되어 만들어진다. 분개모형은 차변/대변 라인과 계정속성을 정하고, 상품계정 매핑은 그 계정속성을 실제 계정으로 바꾼다. ASSIGN / ARG 방식은 분개 라인에 들어갈 금액을 원천값 직접 세팅 또는 집계값 순번 세팅으로 구분해 관리한다. 최종 분개장은 원천 거래, 분개모형, 실제 계정, 금액이 결합된 회계 처리 결과다.
