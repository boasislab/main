세부 포인트

원문 구조별 상세 정리

원문에서 빠졌던 흐름을 보강해, 핵심 논지와 실행 기준을 섹션별로 다시 정리했습니다.

직무보다 작은 단위로 내려가기

  • 직무는 채용, 평가, 보상에는 유용하지만 AX 설계 단위로는 너무 크다. 같은 직무 안에서도 자동화 가능한 Task, AI 보조가 맞는 Task, 사람이 중심이어야 하는 Task가 갈린다.
  • AI는 영업 담당자라는 직무 전체와 일하지 않는다. 고객 정보 검색, 문서 요약, 초안 작성, 이메일 분류, 데이터 추출 같은 구체적 업무와 만난다.
  • Job, Duty, Task, Activity로 해상도를 낮춰야 실제 AI 적용 지점을 볼 수 있다.

Work Map에 담아야 할 것

  • Task 이름만 적는 것이 아니라 입력, 판단 기준, 산출물, 담당자, 사용 시스템, 데이터 출처, 예외 처리, 반복 빈도와 시간을 함께 기록해야 한다.
  • Working Time과 Lead Time을 구분해야 한다. 실제 작업 시간이 줄어도 승인 대기나 검토 병목이 그대로면 리드타임은 줄지 않는다.
  • Task 사이의 연결, 산출물이 어디로 넘어가는지, 피드백이 어떻게 돌아오는지까지 봐야 프로세스 병목을 찾을 수 있다.

기술보다 업무 구조

  • AI Use Case 발굴은 기술적으로 재미있거나 눈에 잘 보이는 업무부터 고르기 쉽다. 하지만 먼저 업무 구조와 병목을 봐야 한다.
  • 보고서 초안 시간이 줄어도 검토자가 처리하지 못하면 병목은 뒤로 이동할 뿐이다. AX는 단위 업무 개선과 전체 흐름 개선을 함께 봐야 한다.
  • 좋은 순서는 Technology → Use Case가 아니라 Work → Problem → Task → Value → Technology다.

AI로 Work Map을 만들되 가설로 다루기

  • AI는 직무분석의 대상이면서 동시에 직무분석을 돕는 도구가 될 수 있다. 문서, 업무 매뉴얼, 양식, 로그를 먼저 읽고 초안을 만들 수 있다.
  • 다만 AI가 만든 Work Map은 정답이 아니라 가설이다. 현업 검증, 실제 데이터 비교, 관찰과 인터뷰로 보완해야 한다.
  • Work Map이 있으면 “AI를 어디에 붙일까”가 아니라 “어떤 Task의 어떤 문제를 어떤 가치 기준으로 바꿀까”로 질문이 바뀐다.

여준님 업무에 적용할 때

  • 직무가 아니라 반복 태스크 목록을 만든다.
  • 각 태스크의 입력·판단·산출물·시스템을 적는다.
  • 자동화 후보와 사람이 승인해야 하는 구간을 구분한다.
