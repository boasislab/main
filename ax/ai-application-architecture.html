원문 수준 상세 정리

원문을 그대로 복제하지 않고, 원문 목차와 논리 흐름을 따라 세부 주장·판단 기준·실행 단계를 촘촘하게 재구성했습니다.

어떤 LLM보다 중요한 질문

  • AI 애플리케이션 설계에서 중요한 질문은 어떤 데이터를 기억하고 어떤 상태를 추적하며 어떤 근거로 답변하게 할지다.
  • 기업용 AI는 고객 정보, 계약, 결제, 운영 데이터, 내부 문서, 규정, 이력, 권한 체계와 연결되는 애플리케이션이다.

확률론적 소프트웨어의 난이도

  • AI 소프트웨어는 같은 입력에도 결과가 달라질 수 있다.
  • mission-critical 업무에는 검색 품질, 데이터 최신성, 권한 제어, 트랜잭션 정합성, 응답 근거, 재현 가능성, 실패 처리가 필요하다.

RAG는 데이터 품질 시스템

  • RAG는 문서 벡터 검색 기능이 아니다.
  • 매뉴얼, 고객 계정 상태, 최근 결제 시도, 장애 공지, 운영 로그, 상품 정책, 환불 규정까지 확인해야 한다.
  • 데이터베이스는 메모리 계층이자 상태 계층이다.

AI 애플리케이션 여섯 계층

  • 추론 계층, 메모리·상태 계층, 검색 계층, 오케스트레이션 계층, 평가 계층, 관측성 계층으로 나눠 볼 수 있다.

검색 품질은 데이터 모델링 문제

  • 문서 생성 시점, 승인자, 최신 버전, 열람 권한, 연결 업무 프로세스, 연결 엔티티를 함께 관리해야 한다.
  • retrieval ranking, reranking, chunking, grounding이 중요하다.

실무형 RAG 파이프라인

  • 의도 분류, 질의 재작성, 메타데이터 필터, 벡터 검색, 전문 검색, 그래프 탐색, 트랜잭션 조회, reranking, 충돌 해결, 감사 로그가 필요하다.

에이전트 상태와 재현 가능성

  • task run, step run, tool call, artifact, approval state를 나눠 저장해야 한다.
  • 모델 버전, 프롬프트 버전, 검색 인덱스 버전, 문서 버전, 권한 상태, 호출 시점의 운영 데이터가 모두 결과에 영향을 준다.

권한과 보안

  • RBAC, ABAC, PII 마스킹, 테넌트 격리가 검색 단계부터 적용되어야 한다.
  • 보안은 프롬프트가 아니라 시스템 경계에서 처리해야 한다.

여준님 업무에 적용할 때

  • 문서 검색과 운영 데이터를 함께 연결한다.
  • 에이전트 단계별 상태와 실패 로그를 저장한다.
  • 답변 근거, 권한, 데이터 최신성, 품질 평가를 설계한다.
