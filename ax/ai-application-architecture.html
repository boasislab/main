원문 구조별 상세 정리

원문에서 빠졌던 흐름을 보강해, 핵심 논지와 실행 기준을 섹션별로 다시 정리했습니다.

모델보다 중요한 질문

  • AI 애플리케이션의 핵심 질문은 어떤 LLM을 쓸 것인가가 아니라 어떤 데이터를 기억하고, 어떤 상태를 추적하며, 어떤 근거로 답변하게 할 것인가다.
  • 기업용 AI는 그럴듯한 답변 생성기가 아니라 고객 정보, 계약, 결제, 운영 데이터, 내부 문서, 규정, 권한 체계와 연결되는 애플리케이션이다.
  • 확률론적 소프트웨어는 같은 입력에도 결과가 달라질 수 있으므로 검색 품질, 데이터 최신성, 권한, 재현 가능성, 실패 처리를 설계해야 한다.

RAG는 데이터 품질 시스템

  • RAG를 문서 벡터 검색 정도로 이해하면 부족하다. 임베딩, 벡터 DB, 메타데이터, 트랜잭션 데이터가 함께 움직여야 한다.
  • 문서가 언제 만들어졌고 누가 승인했는지, 어떤 버전이 최신인지, 누가 볼 수 있는지, 어떤 업무 프로세스와 연결되는지 관리해야 한다.
  • 의도 분류, 질의 재작성, 메타데이터 필터, 벡터 검색, 전문 검색, 그래프 탐색, 트랜잭션 조회, reranking, 충돌 해결, 감사 로그까지가 실무형 RAG다.

여섯 계층과 상태 관리

  • AI 애플리케이션은 추론 계층, 메모리·상태 계층, 검색 계층, 오케스트레이션 계층, 평가 계층, 관측성 계층으로 나눠 볼 수 있다.
  • 에이전트 시스템은 task run, step run, tool call, artifact, approval state를 저장해야 디버깅과 재시도가 가능하다.
  • 모델 버전, 프롬프트 버전, 검색 인덱스 버전, 문서 버전, 권한 상태, 호출 시점의 운영 데이터가 모두 결과에 영향을 주므로 버전 관리가 필요하다.

권한과 경쟁력

  • 권한은 프롬프트가 아니라 시스템 경계에서 처리해야 한다. RBAC, ABAC, PII 마스킹, 테넌트 격리가 검색 단계부터 적용되어야 한다.
  • 모델이 올바른 근거, 올바른 권한, 최신 상태, 재현 가능한 방식으로 업무를 수행하게 만드는 것이 엔지니어링 목표다.
  • 경쟁력은 어떤 모델을 쓰는가, 어떤 데이터를 연결하는가, 어떤 상태를 저장하는가, 어떤 기준으로 품질을 검증하는가에서 갈린다.

여준님 업무에 적용할 때

  • 문서 검색과 운영 데이터를 함께 연결한다.
  • 에이전트 단계별 상태와 실패 로그를 저장한다.
  • 답변 근거, 권한, 데이터 최신성, 품질 평가를 설계한다.
