공유용 일반화 교육자료

거래가 분개장으로 저장되는 절차를 한 번에 본다

이 자료는 내부 프로그램명, 테이블명, 실제 코드값을 제거하고 교육용 개념으로 재구성한 총망라본입니다. 분개 처리 원리, 자동분개 호출구조, 분개모형 전개, 차대 검증, 분개장 저장까지 한 흐름으로 설명합니다.

교육 목표
  1. 분개가 복식부기의 출발점임을 이해한다.
  2. 거래처리와 분개처리를 분리해서 본다.
  3. 분개모형이 실제 분개장 라인으로 전개되는 절차를 익힌다.
Concept

1. 분개처리는 거래를 회계 언어로 바꾸는 과정

보안 식별자 제거
거래처리 프로그램은 업무 거래를 처리하고, 공통 분개엔진은 그 거래를 차변/대변 회계 라인으로 전개한다. 최종 결과는 분개장에 저장되고, 이후 계정원장과 보조원장 대사의 기준이 된다.

원천 거래

상품, 거래유형, 금액, 수량, 통화, 처리일자 같은 업무 데이터를 제공한다.

분개모형

한 거래가 몇 개의 차변/대변 라인으로 나뉘고 어떤 금액을 쓸지 정의한다.

분개장

확정된 계정과 금액이 저장되는 회계 결과 테이블이다.

Call Flow

2. 자동분개 호출구조

거래처리와 분개처리 분리
1. 거래처리매수, 매도, 이자, 평가 같은 업무 거래를 처리한다.
2. 입력 구조 세팅거래코드, 상품코드, 투자목적, 장단기, 참조 원장을 담는다.
3. 공통 분개엔진 호출거래처리 프로그램은 분개장 라인을 직접 만들지 않고 엔진에 위임한다.
4. 분개모형 조회거래유형 기준으로 차변/대변 라인과 계정속성을 가져온다.
5. 계정 확정상품 조건과 계정속성을 결합해 실제 계정을 결정한다.
6. 금액 산출원천 거래 컬럼 또는 사전 계산값을 읽어 각 라인의 금액을 만든다.
7. 차대 검증차변 합계와 대변 합계가 맞는지 확인한다.
8. 분개장 저장검증된 분개 라인을 최종 분개장에 저장한다.
Model

3. 분개모형과 계정매핑의 역할

거래유형어떤 분개모형을 사용할지 결정한다. 예를 들어 채권 매수와 주식 매수는 다른 분개 구조를 갖는다.
→
분개모형차변/대변, 계정속성, 금액 원천, 산식, 순번을 정의한다.
→
계정매핑상품, 투자목적, 장단기, 계정속성을 결합해 실제 계정으로 치환한다.
구성요소쉽게 말하면운영자가 봐야 할 점
거래코드분개모형을 고르는 스위치의도한 거래유형으로 들어왔는지 확인
상품코드계정매핑을 고르는 상품 축상품의 회계 분류가 맞는지 확인
계정속성실제 계정 전 단계의 회계 성격실제 계정코드로 치환 가능한지 확인
금액 원천분개 라인에 들어갈 금액의 출처원천 컬럼과 분개 의미가 맞는지 확인
차대구분차변인지 대변인지 표시차대 합계가 일치하는지 확인

4. 채권 매수 거래 샘플

교육용 일반화

샘플은 “매도가능 장기 국내채권 매수”로 둔다. 실제 코드값 대신 업무 의미만 남기면, 분개모형 호출구조를 교육하기에 가장 적합하다.

입력 항목교육용 값분개 처리에서의 역할
거래유형채권 매수채권 매수용 분개모형을 조회한다.
상품국내채권 상품상품계정 매핑의 기준이 된다.
투자목적매도가능실제 계정 결정 조건으로 사용된다.
장단기장기장기/단기 계정 구분에 사용된다.
참조 원장채권 매수 거래원장취득금액, 지급액, 이자, 세금 등의 금액 원천이 된다.
교육 포인트 채권 매수는 단순 지급액뿐 아니라 취득가, 미지급액, 대체 지급액, 기경과이자, 선수이자, 원천세가 함께 얽혀 있어 분개모형의 역할을 설명하기 좋다.
ERD & Flow

5. ERD와 간략 흐름도로 보는 분개장 생성 개념

첨부 흐름도 개념 반영
ERD는 “어떤 기준정보들이 서로 연결되는가”를 보여주고, 간략 흐름도는 “운용지시가 어떤 순서로 분개장까지 내려가는가”를 보여준다. 두 그림을 함께 보면 자동분개는 거래 데이터, 상품 기준, 거래 기준, 분개모형, 계정매핑이 결합되어 최종 분개장 라인을 만드는 구조로 이해할 수 있다.

ERD 관점: 기준정보가 분개장을 만들기 위해 연결되는 방식

운용지시/원천 거래 작업일자, 거래유형, 종목, 통화, 취득번호, 금액 같은 실제 거래 입력값을 제공한다.
상품/거래 기준 상품코드는 상품계정 매핑으로, 거래코드는 분개모형으로 이어지는 시작 키가 된다.
분개모형/계정매핑 분개모형은 차대 방향과 계정속성을 정하고, 계정매핑은 계정속성을 실제 계정으로 바꾼다.
분개장/원장 확정된 계정, 차대구분, 금액, 거래 식별값이 저장되어 회계 처리 결과가 된다.

간략 흐름도 관점: 운용지시가 분개장으로 내려가는 순서

운용지시→ 상품코드 관리→ 상품-계정상품 매핑→ 계정상품-계정과목 매핑→ 계정과목 확정→ 분개장 저장
운용지시→ 거래코드 관리→ 분개모형 관리→ 차대구분/계정속성 결정→ 분개장 저장
구분입력/관리 항목분개장에 미치는 영향교육용 설명 문장
운용지시 작업일자, 거래유형, 종목, 통화, 취득번호, 금액 분개장에 저장될 거래 식별값과 금액의 원천이 된다. 거래 사실 그 자체를 제공하는 출발점이다.
상품코드 상품분류, 투자목적, 회계상품 구분 어떤 계정상품으로 볼 것인지 결정한다. 같은 거래라도 상품 성격에 따라 계정이 달라진다.
거래코드 매수, 매도, 이자, 평가 등 거래유형 어떤 분개모형을 읽을지 결정한다. 거래코드는 분개모형을 선택하는 핵심 키다.
분개모형 분개순번, 차대구분, 계정속성, 금액 산식 분개장에 몇 줄이 생기고 각 줄이 어떤 의미인지 정한다. 분개모형은 분개장의 설계도다.
계정매핑 계정상품, 계정속성, 계정과목 추상적인 계정속성을 실제 계정과목으로 확정한다. 계정매핑은 설계도 속 계정속성을 실제 계정으로 번역한다.
분개장 거래 식별값, 계정, 차대구분, 금액 회계 처리 결과가 저장되는 최종 산출물이다. 분개장은 거래가 회계 언어로 변환된 결과다.
핵심 정리 상품코드 축은 “어떤 계정으로 볼 것인가”를 정하고, 거래코드 축은 “어떤 차대 구조로 분개할 것인가”를 정한다. 두 축이 분개모형과 계정매핑에서 결합된 뒤 분개장 라인으로 저장된다.

6. 분개처리절차 시뮬레이션

주요 항목 중심
단계처리 내용주요 항목결과
1거래 입력값 수신거래유형, 상품, 투자목적, 장단기, 원천 원장분개엔진 호출에 필요한 키가 준비된다.
2입력 구조 세팅거래 키, 참조 원장명, 원천 금액 식별 정보거래처리와 분개처리 사이의 전달 구조가 완성된다.
3분개모형 조회차대구분, 계정속성, 금액 원천, 산식여러 개의 분개 후보 라인이 만들어진다.
4계정 확정상품, 투자목적, 장단기, 계정속성각 분개 라인의 실제 계정이 결정된다.
5금액 산출취득금액, 지급액, 대체금액, 이자, 원천세분개 라인별 금액이 계산된다.
6차대 검증차변 합계, 대변 합계합계가 맞으면 저장 가능, 맞지 않으면 오류로 중단한다.
7분개장 저장거래 식별값, 계정, 차대구분, 금액최종 분개장이 생성된다.

채권 매수 분개모형 전개 예시

분개 의미차대 방향금액 원천교육용 설명
취득가차변취득금액 및 관련 조정금액채권 자산으로 인식할 금액이다.
기경과이자차변일반/할인/할증 이자 항목매수 시점까지 이미 경과한 이자 성격을 분리한다.
미지급액대변미결제 금액아직 지급되지 않은 채무 성격 금액이다.
지급액대변현금 지급 금액실제 지급된 결제 금액이다.
지급액 대체대변대체 지급 금액현금 외 대체 처리된 결제 금액이다.
선수이자대변미리 받은 이자 성격 금액수익 또는 부채 성격으로 분리 관리한다.
예수원천세대변일반/할인/할증 원천세 항목세금 예수 성격으로 별도 분개한다.

7. 교육과 운영 점검 체크리스트

교육할 때 강조할 문장

  • 거래처리 프로그램은 분개를 직접 저장하지 않고, 분개엔진에 필요한 키를 넘긴다.
  • 분개모형은 차변/대변 구조를 만들고, 계정매핑은 실제 계정을 확정한다.
  • 금액은 원천 거래값 또는 사전 계산값을 기준으로 라인별로 채워진다.
  • 차변 합계와 대변 합계가 맞아야 분개장 저장이 가능하다.

운영자가 확인할 항목

  • 거래유형이 올바른 분개모형을 호출했는가
  • 상품 조건과 계정속성이 실제 계정으로 매핑되는가
  • 원천 금액 항목의 업무 의미가 분개 의미와 맞는가
  • 차대 검증 후 분개장, 계정원장, 보조원장 대사가 맞는가

한 장 결론

분개처리는 “거래 입력값 → 분개엔진 입력 구조 → 분개모형 조회 → 계정 확정 → 금액 산출 → 차대 검증 → 분개장 저장”의 절차로 이해하면 된다. 채권 매수 샘플은 이 흐름을 설명하기 좋은 사례이며, 교육자료에서는 실제 내부 식별자보다 각 항목의 역할과 검증 포인트를 중심으로 설명하는 것이 효과적이다.
